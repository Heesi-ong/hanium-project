# 최종 화면 테스트 기준

## 실행 조건

- 백엔드: `Back` 디렉토리에서 `../.venv/bin/uvicorn app.main:app --reload`
- 프론트: `Front` 디렉토리에서 `npm run dev`
- 프론트 주소: `http://127.0.0.1:5173`
- 백엔드 주소: `http://127.0.0.1:8000`

## 공통 화면

- 상단 메뉴의 `영상 업로드`, `분석 이력` 링크가 각각 올바른 화면으로 이동한다.
- 현재 화면의 상단 메뉴가 활성 상태로 표시된다.
- 존재하지 않는 프론트 경로는 공개 메인 페이지(`/`)로 이동한다.
- 로그아웃 상태에서 `/upload`, `/results`, `/result/:id`, `/chat` 접근 시 `/login`으로 이동한다.
- 로그인 후 원래 요청한 보호 화면으로 이동한다.
- 데스크톱과 모바일에서 콘텐츠가 화면 밖으로 가로 스크롤되지 않는다.
- 키보드 포커스가 버튼, 링크, 입력창에서 명확하게 표시된다.

## 업로드 화면

- 허용 파일 형식과 500MB 제한 안내가 표시된다.
- 비어 있거나 재생할 수 없는 영상은 작업 생성 전에 `400`으로 거부된다.
- 500MB 초과 파일 선택 시 업로드 전에 오류 메시지가 표시된다.
- 업로드 중 진행률과 분석 중 상태 메시지가 구분되어 표시된다.
- 업로드 완료 시 작업 ID가 생성되고 분석 상태를 주기적으로 확인한다.
- 현재 분석 단계와 서버 진행률이 표시된다.
- 대기 또는 처리 중인 분석을 취소할 수 있다.
- 실패 또는 취소 작업의 원본이 보존된 경우 재시도할 수 있다.
- 서버 재시작 후 처리 중 작업이 대기열에서 다시 실행된다.
- 서버 재시작 후 처리 중 작업과 관계없는 고아 프레임 디렉토리가 자동 삭제된다.
- 분석 완료 시 상세 결과 화면으로 이동한다.
- 분석 중 다른 화면으로 이동해도 서버에서 작업이 계속 진행된다.
- 네트워크 또는 CORS 오류 시 통일된 연결 오류 메시지가 표시된다.

## 결과 목록 화면

- 결과 조회 성공 시 상태, 점수, 처리 시간, 생성일이 표시된다.
- 로그인 사용자 본인의 분석 작업만 표시된다.
- 검색, 상태 필터, 정렬 기준이 정상 작동한다.
- 검색, 상태 필터, 정렬, 페이지네이션은 서버 API 조건으로 처리된다.
- 완료 결과의 카드 또는 `상세 보기` 버튼으로 상세 화면에 이동한다.
- 삭제 확인 취소 시 결과가 유지된다.
- 삭제 중에는 해당 삭제 버튼이 비활성화되고 `삭제 중...`으로 표시된다.
- 삭제 성공 후 목록이 갱신되고 성공 메시지가 표시된다.
- 이미 삭제된 결과 등 삭제 실패 시 서버 오류 메시지가 화면에 표시된다.

## 결과 상세 화면

- 파일명, 총점, 요약 피드백, 영상 길이, 타임라인 수, 처리 시간이 표시된다.
- 핵심 점수 카드와 발표 속도, 필러, 손동작, 음량 섹션 카드가 표시된다.
- 없는 값은 화면 오류 없이 `-`로 표시된다.
- 감지되지 않은 자세, 얼굴, 어깨, 얼굴 방향 지표는 낮은 점수와 구분하여 `측정 불가`로 표시된다.
- 측정 불가 지표는 종합 점수 가중치에서 제외되고 사용 가능한 지표로 가중치가 재계산된다.
- 자세·얼굴 감지율은 분석 신뢰도로만 표시되고 종합 점수 가중치에 포함되지 않는다.
- 최소 유효 프레임과 감지율 기준에 미달한 시각 평가는 측정 불가로 표시된다.
- 타임라인 영역에서 평균, 최고, 최저 점수와 시간대별 상세 지표가 표시된다.
- `목록`, `새 분석`, `새로고침` 버튼이 올바르게 동작한다.
- 존재하지 않는 결과 접근 시 한국어 오류 메시지와 복구 버튼이 표시된다.
- Markdown 보고서를 내려받을 수 있다.
- 분석 결과를 AI 코치 상담 문맥으로 연결할 수 있다.
- 연습 코칭 API 요청이 실패해도 기본 결과와 타임라인이 표시된다.
- 타임라인 API 요청이 실패해도 기본 분석 결과와 연습 코칭이 표시된다.
- 결과 상세 화면을 빠르게 전환해도 이전 결과의 응답이 새 결과에 표시되지 않는다.
- 연습 코칭 실패 상태에서 `코칭 다시 불러오기`가 실패한 기능만 다시 요청한다.
- 발표 내용 보조 분석에 근거 문장과 Whisper 발화 시점이 표시된다.
- 발표 내용 보조 분석이 휴리스틱이며 신뢰도에 한계가 있음을 표시한다.

## 성장 추이 및 계정

- 성장 추이 화면에는 완료 분석의 총점과 주요 지표가 시간 순서로 표시된다.
- 성장 변화량은 동일 발표 목적과 동일 연습 시리즈 결과 사이에서만 계산된다.
- 같은 이름으로 새로 만든 두 시리즈는 서로 다른 `series_id`를 사용한다.
- 업로드 화면에서 기존 연습 시리즈를 선택해 반복 발표를 연결할 수 있다.
- 기존 연습 데이터에 `series_id`가 없으면 동일 목적과 정규화된 시리즈 이름으로 비교한다.
- 계정 화면에서 표시 이름과 비밀번호를 변경할 수 있다.
- 전체 로그아웃과 계정 탈퇴가 정상 동작한다.
- 계정 탈퇴 시 해당 사용자의 분석 결과 파일과 원본 파일이 함께 삭제된다.
- 계정 화면에서 사용자별 저장 공간과 동시 분석 수를 확인하고 데이터를 JSON으로 내보낼 수 있다.

## AI 코치

- 대화 이름 변경, 보관, 삭제가 사용자 소유권을 확인한 뒤 처리된다.
- 보관된 대화를 별도 목록에서 조회하고 복원할 수 있다.
- 응답 복사와 마지막 응답 재생성이 동작한다.
- 응답 중단 시 클라이언트 대기가 종료된다.
- 대화 및 메시지 목록 API가 서버 페이지네이션을 지원한다.
- 예상 질문 선택 시 질문은 AI 청중 질문으로 표시되고 사용자 답변 입력창은 비어 있다.
- 예상 질문 답변 제출 후 명확성, 근거, 간결성, 설득력 평가와 개선 예시, 후속 질문을 제공한다.

## 연습 데이터 수명주기

- 결과 삭제, 계정 삭제, 자동 보존 기간 정리 시 연결된 연습 컨텍스트도 제거된다.
- 사용자 데이터 내보내기에 연습 목적, 목표 및 계산된 개선 계획이 포함된다.
- `./scripts/check-practice-contexts.sh` 실행 결과가 `orphan_practice_contexts=0`이다.

## 반응형 기준

- 1280px: 상세 요약이 점수 원형, 피드백, 메타 정보 3영역으로 표시된다.
- 1024px 이하: 상세 메타 정보와 점수 카드가 자연스럽게 재배치된다.
- 768px 이하: 헤더 버튼과 상세 섹션이 한 열로 표시된다.
- 390px 모바일: 메뉴, 버튼, 카드, 타임라인 지표가 잘리지 않고 읽을 수 있다.

## API 기준

- `OPTIONS /analyze/upload` 요청이 허용 출처에 대해 `200`을 반환한다.
- 로그인하지 않은 `/analyze/*` 요청은 `401`을 반환한다.
- 다른 사용자의 분석 작업 조회·상세·삭제 요청은 `404`를 반환한다.
- 분석 업로드는 `202`와 `QUEUED` 작업 ID를 반환한다.
- 동일한 `Idempotency-Key` 분석 업로드는 새 작업을 만들지 않고 기존 작업을 반환한다.
- 동일한 `Idempotency-Key`의 완료된 채팅 요청은 중복 실행하지 않는다.
- 요청 본문 크기가 업로드 제한을 초과하면 multipart 처리 전에 `413`을 반환한다.
- 사용자 저장 용량 또는 동시 분석 제한을 초과하면 새 업로드를 거부한다.
- 분석 취소와 재시도 API가 타 사용자의 작업을 숨긴다.
- 완료 작업의 결과 파일이 사라지면 DB 상태를 실패로 전환한다.
- 결과 파일의 핵심 점수와 DB 점수가 다르면 결과 파일 기준으로 DB 핵심 요약을 동기화한다.
- 완료 결과 보존 기간이 `0`이면 자동 삭제하지 않고, 명시적으로 설정한 경우에만 기간이 지난 완료 결과를 정리한다.
- 요청 제한 초과 시 `429`와 한국어 메시지를 반환한다.
- 없는 상세 결과 조회는 한국어 메시지와 함께 `404`를 반환한다.
- 없는 결과 삭제는 한국어 메시지와 함께 `404`를 반환한다.
- 프론트는 문자열, 배열형 검증 오류, 일반 메시지를 동일한 오류 처리 흐름으로 표시한다.

## 빌드 기준

- `npm run build`가 오류 없이 완료된다.
- `npm run lint`, `npm run test`, Ruff 검사가 오류 없이 완료된다.
- 변경한 백엔드 Python 파일이 문법 오류 없이 컴파일된다.
- DB 백업 덤프가 완료되고 마이그레이션을 두 번 실행했을 때 두 번째 실행은 변경 사항이 없다.
